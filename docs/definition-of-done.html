You're Not Done When You Think You're Done

Definition of Done

Home Page

You write the last line of code. You run it. It works. You check the requirements. Everything looks fine. You move the task to "Done."

Then the tester finds bugs. Things you never thought of. Things not in the requirements.

You feel frustrated. But the real problem is not the tester. The real problem is your definition of "done."

Here is a better way to think about it. It comes from science.

In science, a good theory is not one that is "complete." A good theory is one that you can try to break. You come up with experiments. You try to prove it wrong. You try to find its limits. If you cannot find any way to break it — even after trying hard — then the theory is useful.

But if a theory is "complete" and has no way to be broken? That is not science. That is metaphysical pseudoscience. It sounds deep. It sounds perfect. But it is useless. Because you cannot test it. You cannot improve it. It just sits there like a fantasy.

The same applies to your work.

When you finish your first version, do not call it "done." Call it "complete on paper." That is like a theory that looks perfect but has never been tested. It might be wrong. You just don't know yet.

So what do you do? You try to break it. On purpose.

You test edge cases. You feed it bad inputs. You ask a colleague to poke holes. You run it in different conditions. You think like a tester, not like the person who wrote it.

And you keep doing this until you run out of ways to break it.

That is your real definition of done. Not perfection. Not "zero bugs forever." Just this: you honestly tried everything reasonable to make it fail, and it didn't fail. So you stop.

This is grounded. This is practical.

If you never try to break your work, then your "done" is like an unfalsifiable theory. It feels complete. But it has no connection to reality. And when someone finally touches it — a tester, a user, a real audience — it will crack open. Because you never attacked it yourself.

Do not chase perfection. That is a trap. But also do not stop at the first working version. Stop only after you have tried and failed to break it.

That is how science works. That is how good work works.

So next time you think you are done, ask yourself: have I run out of ways to break this? If not, you are still in the fantasy stage. Keep going. Only when you cannot break it anymore — then you are truly done.
